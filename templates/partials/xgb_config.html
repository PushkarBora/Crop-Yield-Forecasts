Grid Search Configuration

Define parameter ranges for exhaustive search. The system will test all combinations using TimeSeriesSplit cross-validation to find the optimal configuration.

💡 Number of past time steps used as input features. Example: 2 to 5 by 1 → tests [2, 3, 4, 5]
💡 Number of boosting rounds. Example: 50 to 300 by 50 → tests [50, 100, 150, 200, 250, 300]
💡 Maximum depth of each tree. Deeper trees = more complex patterns but risk overfitting. Example: 2 to 6 by 1 → tests [2, 3, 4, 5, 6]
⚙️ Boosting learning rate (eta). Smaller = slower but more precise. Example: 0.01 to 0.2 by 0.05 → tests [0.01, 0.06, 0.11, 0.16]
💡 Fraction of training samples used per boosting round. Helps prevent overfitting. Example: 0.6 to 1.0 by 0.2 → tests [0.6, 0.8, 1.0]
💡 Fraction of features used per tree. Adds randomness to reduce overfitting. Example: 0.6 to 1.0 by 0.2 → tests [0.6, 0.8, 1.0]
